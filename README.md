## 🧭 功能总览

QQ 官方机器人能做的群管理动作有限，插件把这部分能力整理成一套「在群里直接说」的指令，同时把配置做进了 WebUI 面板。

| | 能力 | 说明 |
| --- | --- | --- |
| 🔨 | **禁言与解禁** | 一次艾特多人、组合时长、默认时长，随时查询当前禁言情况 |
| 🎫 | **入群审批** | 申请卡片带按钮，群主/群管和插件群管都能一键处理；也可以引用通知回文字审批 |
| 🧮 | **进群验证** | 算术题或自定义问答，未验证发言自动撤回，答错/超时按配置禁言，管理员可一键免除 |
| 🔍 | **关键词风控** | 入群回答的白词放行、黑词拦截；群消息违禁词自动禁言、撤回，支持正则表达式、链接消息与二维码图片自动撤回 |
| 🚦 | **刷屏监控** | 按 1 秒 / 1 分钟 / 1 小时窗口统计成员发言频率，超限自动撤回近期消息并禁言，支持夜间限速 |
| 🖥️ | **服务器运行状态** | 单页总览，展示 CPU、内存、SWAP、磁盘、网络、进程和 QQ 官方平台在线状态；支持状态图片与毛玻璃配置；`查看状态`/`状态` 指令已开放给所有平台（QQ 官方仅群聊，其他平台群聊和私聊均可用） |
| 🔔 | **进退群通知** | 自定义欢迎与退群文案，支持艾特成员和成员头像 |
| 🗂️ | **分群配置** | 每个群独立的群管名单、功能开关、词表与安全限制，也可全局统一 |
| 🧠 | **模型工具** | 把禁言、解禁、查询和审批交给 LLM 调用，可选严格身份审查 |
| 🧩 | **淼淼菜单** | `/菜单` 发送带按钮菜单，可查看功能图片、使用指南、帮助和群管面板；QQ 官方走原生键盘，钉钉走互动卡片按钮（需 AstrBot 4.29.4+），其他平台发送文字菜单 |
| 📣 | **群广播** | WebUI 编辑文字、上传图片，一键发送到插件已知的全部群 |
| 🆔 | **群 UID** | 自动分配 `100001` 起的群编号，退群释放空号并优先复用；群组列表和群管面板同步显示 |
| 🖥️ | **WebUI 控制台** | 在 AstrBot 插件详情页直接处理申请、验证、群管、广播、数据导入导出与配置，无需回群操作；导航栏右侧可检查更新 |

### 支持平台

| 平台 | 支持情况 |
| --- | --- |
| `qq_official` / `qq_official_webhook` | 完整功能：群管面板、审核/验证、广播、菜单、状态图片 |
| `dingtalk` | 菜单互动卡片（AstrBot 4.29.4+）、面板图片、群管帮助、状态图片；群管面板/审核/验证不可用，群广播仍只发 QQ 官方群 |

<a id="webui"></a>

## 🖥️ WebUI 群管控制台

插件自带一个与 AstrBot 插件市场视图风格一致的可视化页面，入口在：

**AstrBot WebUI → 插件 → QQ官机群管 → 可视化视图 → 群管控制台**

控制台包含以下页面与监控子页签：

| 页签 | 能做什么 |
| --- | --- |
| 总览 | 待审申请、验证队列、群组数量、插件群管、功能开关与运行状态 |
| 入群审批 | 查看申请资料与问答，直接同意或拒绝；拒绝可填写理由。群标识优先显示备注，其次接口群名，最后群 UID；申请记录不会因 QQ 列表接口延迟而自动消失，可点「删除」只清理后台记录（不处理 QQ 申请） |
| 进群验证 | 查看题目、答错次数与剩余时间，放行或重新出题；群标识同样优先显示备注/群名，没有时显示群 UID |
| 群组 | 查看群名称、群 UID、群 OpenID、群 UMO、配置来源、群管名单；添加/移除插件群管。群里发过消息、出现过申请/验证或已有配置的群都会自动记录；群 UID 从 100001 递增并在退群后复用空号；群 OpenID 是 QQ 官方机器人的 `group_openid`，不是 QQ 群号；可为每个群添加备注，详情按钮可「获取群名 / 刷新群名」，列表右上角支持「一键获取群名」 |
| 刷屏监控 | 展示防刷屏状态、追踪群数、追踪用户、活跃用户、当前速率限制配置和实时追踪用户表；数据每 5 秒自动刷新 |
| 服务器运行状态 | 单页总览，每 5 秒刷新；支持状态图片上传、采样间隔和毛玻璃配置。QQ 官方平台隐藏好友数、群成员数、协议版本与 QQ 头像，群聊数量使用插件已知群数 |
| 配置 | 编辑全局或分群配置，支持开关、词表、题库、模板与安全限制；删除分群配置的入口名称为「恢复继承全局」；保存/创建分群配置会自动启用分群覆盖，群选择器显示群名（没有群名时显示群 UID） |
| 群广播 | 编辑广播文字、上传 PNG/JPG 图片，一键发送到插件已知的全部群；文字和图片分两条消息发送 |
| 数据 | 导出或安全导入 `state.json` / 配置快照，查看视图与运行信息；导入前会预览影响范围并自动备份；还包含群管面板三张图片的上传、替换和删除 |

视图只在已登录的 AstrBot Dashboard 中通过受限 iframe 加载，所有操作经 bridge 转发到插件后端，并复用 Dashboard 会话鉴权。视图里的审批、放行和禁言解除会直接调用 QQ 接口，操作前请确认群与成员。

导航栏最右侧的「检查更新」只读取 GitHub 最新 Release 版本号：有新版本时提示“有新版本：vX.X.X”，否则提示已是最新。它不会下载、覆盖或自动更新插件。

右上角的**调色盘**可以更改控制台主色：支持 6 个预设色和自定义取色。主题色只影响这个控制台，不会修改 AstrBot 其他页面；保存后写入插件数据目录的 `state.json`，下次打开自动恢复。

群备注除了在群组页点「添加备注」外，也可以直接在群里发 `群绑定 群号 [群名]`，例如 `群绑定 123456789 天文社`。备注只用于显示，底层群身份始终是 `group_openid`。

群组详情里的「获取群名 / 刷新群名」会调用 QQ 官方 `GET /v2/groups/{group_openid}/info` 并缓存真实群名。该接口需要 QQ 开放平台白名单权限；没有权限返回 `11253` 时会提示，不影响群备注和群 UID。显示优先级为：群备注 → 接口群名 → 群 UID。群组列表右上角的「一键获取群名」会批量获取未命名 QQ 群，每次最多 30 个，超过后会提示剩余数量。

## 📦 安装与准备

### 版本要求

插件声明的最低版本是 **AstrBot 4.26.0**，原因是配置面板和 WebUI 视图用到了几个逐个版本才落地的组件：

| 面板能力 | 所需版本 | 上游改动 |
| --- | --- | --- |
| 开关联动显示（`condition`） | 4.0.0 | [#2433](https://github.com/AstrBotDevs/AstrBot/pull/2433) |
| 分群列表（`template_list`） | 4.10.4 | [#4208](https://github.com/AstrBotDevs/AstrBot/pull/4208) |
| 折叠条目显示 UMO（`display_item`） | 4.25.3 | [#8228](https://github.com/AstrBotDevs/AstrBot/pull/8228) |
| 插件 Web API（`astrbot.api.web`）与视图 bridge | 4.26.0 | [#5940](https://github.com/AstrBotDevs/AstrBot/pull/5940) |

已完成的联调版本是 **4.26.8**；4.25.3 上可继续使用 2.8.x，但本版本声明的最低版本是 4.26.0，因为 WebUI 视图依赖该版本才提供的插件 Web API。低于 4.26.0 时请在插件管理器提示中先升级 AstrBot。

### 安装方式

**方式一：上传 ZIP（推荐）**

WebUI → 插件管理 → 安装插件 → 上传 `astrbot_plugin_qq_group_manage.zip`。AstrBot 会自动读取 `requirements.txt` 并安装依赖（本插件只额外依赖 `regex`，用于给进群正则匹配加超时保护）。

**方式二：从仓库安装**

在插件管理里填写仓库地址：

```
https://github.com/1023286457/astrbot_plugin_qq_group_manage
```

**方式三：手动放置**

把插件目录整个放进 `data/plugins/`，安装 `requirements.txt` 中的依赖后重载插件。

### 使用前必须确认

1. 平台适配器为 `qq_official`、`qq_official_webhook` 或 `dingtalk`。QQ 需开启群 / C2C 事件；钉钉菜单按钮需 AstrBot 4.29.4+。
2. QQ 官方机器人需是目标群管理员，并拿到对应的群管理接口权限；钉钉平台仅支持菜单、图片和状态等通用功能，群管面板/审核/验证不可用。
3. 想用卡片按钮：机器人有自定义 Markdown 与按钮权限；Webhook 模式下还要订阅 `INTERACTION_CREATE` 事件。
4. 想用进群验证和违禁词撤回：机器人必须能收到群内**全部消息**，只在被 @ 时才收到消息的模式无法工作。

### 从旧版本升级（目录改名了）

插件目录已从 `astrbot_plugin_qq_group_admin` 改为 `astrbot_plugin_qq_group_manage`，配置文件和数据目录路径随之变化。按顺序操作可完整保留配置：

1. 关闭 AstrBot。
2. `data/config/astrbot_plugin_qq_group_admin_config.json` → 改名为 `astrbot_plugin_qq_group_manage_config.json`。
3. `data/plugin_data/astrbot_plugin_qq_group_admin/` → 改名为 `astrbot_plugin_qq_group_manage/`。
4. 卸载或删除旧的插件目录（卸载时不要勾选删除配置与数据）。
5. 启动 AstrBot，安装新版插件。

如果是全新安装，直接跳过 2～4。旧版配置里写死的 `plugin_set` 白名单仍然兼容旧名字，不必手动改。

## ⌨️ 指令速查

在群里 **@机器人** 后直接发指令即可，不用额外加 `/`。QQ 快捷指令自动补 @机器人 时，也只填指令正文。

如果你习惯带前缀，可以在 AstrBot 当前会话的配置里设置「唤醒词」，例如 `!`，然后发 `!群管帮助`。`/` 只是可选唤醒词之一——会话没有配置 `/` 时，`@机器人 /群管帮助` 是匹配不上的。

| 指令 | 作用 |
| --- | --- |
| `禁言 @用户 [时间]` | 禁言一个或多个成员，省略时间按默认 **1 分钟** |
| `解禁 @用户` | 解除指定成员禁言 |
| `禁言状态` | 查看全员禁言规则与当前被禁言的成员 |
| `添加群管 @用户` / `删除群管 @用户` | 维护本群插件群管名单 |
| `群管列表` / `群管帮助` | 查看群管名单、可用指令 |
| `菜单` | 发送三行两列的淼淼菜单：功能列表、使用指南、群管面板、群管帮助、运行状态、获取帮助；QQ 官方为原生键盘，钉钉为互动卡片按钮，其他平台为文字菜单 |
| `查看状态` / `状态` | 生成服务器运行状态图片发到当前会话，失败时降级为文字；所有平台可用（QQ 官方仅群聊，其他平台群聊和私聊均可用） |
| `群绑定 群号 [群名]` | 把本群 `group_openid` 绑定到 QQ 群号备注，例如 `群绑定 123456789 天文社` |
| `群管功能` | 查看并调整本群功能开关，点状态即填入修改指令 |
| `验证列表` / `验证放行 @用户` / `重新验证 @用户` | 进群验证管理，详见[进群验证](#verify) |

**时间写法**：`30秒`、`10分`、`2小时`、`1天2小时` 都行，纯数字按分钟处理；填 `0`、`解除`、`解禁` 表示解除禁言。默认时长在面板里改。

### 菜单与群管面板

在群里发送 `菜单`，机器人会发送一条带按钮的 Markdown 菜单：

- 第一排：`功能列表`、`使用指南`
- 第二排：`群管面板`、`群管帮助`
- 第三排：`运行状态`、`获取帮助`
- 点击 `功能列表`、`使用指南`、`获取帮助` 会发送在 **WebUI → 数据 → 群管面板图片** 上传的对应图片
- 点击 `群管面板` 会发送一条面板消息：上方文本显示入群审核申请、入群人机验证状态和本群群 UID，下方依次是「入群审核申请」标签行、开/关按钮、「入群人机验证」标签行、开/关按钮
- 点击 `群管帮助` 会优先发送与 `群管帮助` 指令相同的帮助图片，只有图片生成/发送失败时才降级为文字
- 点击 `运行状态` 与发送 `查看状态` / `状态` 指令效果相同，所有群成员都可以使用
- 状态文字和群聊 UID 都是文本；标签行是 QQ 键盘的只读按钮样式（QQ 不允许键盘里出现纯文本行），点标签不会修改配置
- 开关按钮只有 QQ 群主/管理员可点；修改只作用于当前群，和全局不同时自动创建/更新分群配置，改回与全局相同后恢复继承全局

**钉钉平台**（需 AstrBot 4.29.4+，跨平台按钮组件）：

- `菜单` 发送钉钉互动卡片按钮，布局与 QQ 菜单相同；群聊和机器人私聊都可用
- 点击行为与 QQ 菜单一致：面板图片、群管帮助图片（失败降级文字）、运行状态图片（失败降级文字）
- 点击 `群管面板` 会提示「此平台不支持群管面板」：入群审核申请、入群人机验证只在 QQ 官方群生效，群管面板和开关仅 QQ 官方机器人可用
- 钉钉群消息会被自动记录到 WebUI 群组页，便于查看；群广播仍只发送到 QQ 官方群
- 其他平台（Telegram、Discord 等）发送 `菜单` 会收到文字菜单

**几个边界**：

- 禁言只对普通成员生效；全员禁言目前只提供查询，不支持设置。
- 一条消息最多处理前 10 个被艾特的成员。
- QQ 官方按钮键盘最多 5 行、每行最多 5 个按钮，即单条消息最多 25 个按钮。
- 多人操作时，某个成员失败不会中断，其余成员继续处理，最后汇总成功人数、失败成员和原因。

<a id="approval"></a>

## 🎫 入群审批

申请卡片会显示昵称、申请时间、来源、风险提示和验证内容，但**不会暴露成员 OpenID 和申请 ID**。

### 方式一：点卡片按钮

点完即完成审批，群里立刻收到结果，不需要再补一条指令。

| 按钮 | 谁能点 |
| --- | --- |
| 群管同意 / 群管拒绝 | QQ 原生群主与群管理员。由 QQ 的「仅管理员可操作」按钮权限直接限制 |
| 授权同意 / 授权拒绝 | 发卡时的 AstrBot 管理员 + 本群插件群管。QQ 端限定指定用户可点，插件再实时复核一次名单 |

点「拒绝」不需要填理由。申请处理完成后，这张卡上的所有按钮立即失效。

### 方式二：引用通知回文字

**引用机器人发出的那条申请通知**，发送下面任意一种：

```
同意
通过
拒绝
拒绝 未完成入群验证
```

定位逻辑用的是 QQ 原消息 ID 或引用索引：发通知时记录 `ext_info.ref_idx`，引用时比对 `message_scene.ext` 里的 `ref_msg_idx` 或引用元素的 `msg_idx`。只认当前平台、当前群的待审记录，同时校验操作者权限。

指令可以不带前缀，也支持当前会话配置的唤醒词（`!同意`、`!拒绝 理由`）；旧写法 `/同意`、`/拒绝 理由` 仍然可用。卡片按钮不受唤醒词影响。

### 审批的公共规则

- **一把锁**：按钮、引用回复、LLM 工具共用同一个处理锁，并发点击不会重复提交。
- **找不到就明说**：索引缺失、冲突、匹配不到，或申请已处理/已过期，插件会直接提示，不再把消息丢给默认 LLM。
- **降级**：按钮发送失败时通知自动降为纯文本，但仍会保存响应里的引用索引。
- **旧通知**：没保存引用索引的历史通知仍可通过原消息 ID 审批；实在匹配不上就用卡片按钮。
- **2.6.0 起移除**：申请编号、编号审批指令、`/群申请归零` 均已下线，旧通知上的编号按钮不再有效。LLM 的申请审批工具独立保留。

<a id="verify"></a>

## 🧮 进群验证

在面板「⑨ 进群验证」里开启，或由有权限的群管发送 `群管功能 进群验证 开启`。默认关闭，开启前已经在群里的成员不受影响。

新成员入群后，原有欢迎通知照常发送，机器人再单独发一道题。出题前会先调用 QQ 的 `bot_state` 查询机器人在本群的角色：**只有机器人是群主或管理员时才自动出题**；确认机器人只是普通成员时会跳过。该接口是白名单接口，拿不到角色时无法判断，插件会保留兼容行为继续出题，并在日志中提示。

| 题型 | 怎么作答 |
| --- | --- |
| **算术题**（默认） | 随机加减乘除，下方 4 个选项按钮只有本人能点。选错立刻换新题，避免挨个试选项 |
| **自定义问题** | 面板中按 `问题 => 正则` 一行一条，如 `本群主题是什么？ => ^(天文\|astronomy)$`，随机抽一条。成员直接在群里发答案，默认忽略大小写 |

算术题的选项下面还有一个 **「管理员免除」** 按钮：QQ 端限定**群主/群管理员**可见可点，服务端点击时再实时复核一次身份。点一下就把该成员放行，如果对方已因验证失败被禁言，会同步解禁。按钮只出现在新发出的卡片上；插件群管或 AstrBot 管理员如果没有 QQ 群管理身份，看不到这个按钮，改用 `验证放行 @用户`。

### 各状态的处理

| 情况 | 行为 |
| --- | --- |
| 未验证就发言 | 撤回消息 + 提醒先完成验证。同一成员 30 秒内只提醒一次（撤回不受限制），消息不会进入指令、违禁词或 LLM |
| 答错 | 达到「允许答错次数」（默认 3 次）后按「验证失败禁言时长」（默认 1 天）禁言，进入「验证失败」状态，期间发言同样撤回 |
| 超时 | 「验证限时」默认 10 分钟，填 0 表示不限时，从题目成功发出后开始计时。超时处理可选 `不处理` / `提醒一次` / `按失败禁言`，每人只执行一次 |
| 题目没发出去 | 例如无主动消息权限或额度用完、换题失败：不计时也不禁言。成员发言时机器人会回复补发文字题（这条消息不算作答），补发成功才开始计时，失败就等下次发言 |
| 验证通过 | 记录立即删除，之后正常发言 |
| 成员退群 | 自动清理该成员的验证记录 |

### 验证指令

| 指令 | 作用 |
| --- | --- |
| `验证列表` | 查看本群未完成验证的成员、答错次数、剩余时间 |
| `验证放行 @用户` | 直接跳过验证；若因验证失败被禁言，同时解禁 |
| `重新验证 @用户` | 重新出题并清零答错次数，也可让已在群里的成员补做验证 |

以上指令需要本群群管权限。题型在 `群管功能` 里切换；题库、次数、时长和题目模板请到面板修改。

### 依赖条件

1. 机器人是群管理员，否则无法撤回消息、无法禁言；插件会在出题前检查 `bot_state`，确认不是管理员时跳过自动出题。撤回只对 **2 分钟内** 普通成员的消息有效。
2. 机器人必须收到群内全部消息，只收 @ 消息时发现不了未验证成员的发言。
3. 算术题按钮依赖自定义 Markdown 与按钮权限，Webhook 需订阅 `INTERACTION_CREATE`。按钮发不出去时题目降级为纯文本，改为直接回复答案数字。
4. QQ 不允许用进群事件被动回复，题目按主动消息发送，会占用每群每日主动消息额度。

> 自定义问题正则写错或匹配超时：本次作答不计入答错次数，并提示联系管理员；没有任何有效自定义问题时，自动改用算术题。
>
> QQ 官方尚未开放移出群成员接口，所以验证失败只能禁言，暂时无法踢人。

<a id="keywords"></a>

## 🔍 关键词与内容风控

### 配置入口

面板「② 全局与分群配置」→ 展开全局配置或目标群 UMO →「⑧ 关键词管理」。

入群自动审批、消息违禁词禁言、违禁词撤回**默认全部关闭**。进群白词、黑词、消息违禁词默认都按**普通文本包含匹配**；进群白黑词另可切换正则。默认忽略大小写和词条首尾空格，空词条不生效。

### 入群白词与黑词

开启「入群关键词自动审批」后，只检查申请里用户填写的**问题回答**：

- 任一回答命中白词 → 自动同意；命中黑词 → 自动拒绝。规则逐条匹配每个回答，不会把多条回答拼在一起。
- 两类都命中时（包括分别落在不同回答上），按「优先规则」执行，默认**黑词优先**，可改为白词优先。
- 没有命中、没有回答或词表为空时不作判断，继续走人工审批。问题文字、昵称、单独的验证消息都不参与匹配。
- 自动审批成功就不再发待审卡片，已有的待审映射会清理；失败只记日志，并（在通知开启时）发人工审批通知。QQ 已自动通过的申请只发结果通知，不留待审记录或按钮。插件审批完成后会写完成标记，保留期限内阻止重复事件再次审批或重新生成卡片，重载后依然有效。

### 包含匹配 vs 正则匹配

**包含匹配（默认）**：只填词就行。填 `广告`，回答「我来发广告」就会命中；`a.b`、`C++`、`[` 都当普通字符，不需要转义。旧词表可以原样沿用。

**正则匹配**：把「进群匹配模式」设为「正则匹配」，每条填一个正则，**不加** `/.../`。例如：

- `^(天文|摄影)爱好者$` 只匹配完整回答
- `广告|推广` 匹配其中任意一种

默认忽略大小写，可用 `(?-i:ABC)` 局部区分大小写；`\d`、`\D` 这类转义本身含义不同，增删时按原样区分。切换模式不会改写现有词表，切之前先确认旧词条在新模式下还对不对。

正则模式下，群内添加或切换到该模式会校验语法；面板里保存的规则不合法、或单次匹配超过 **50 毫秒**，本次直接停止自动审批、记日志，并在通知开启时转人工——不会跳过有问题的黑词后放行。

这套逻辑独立于「入群申请通知」「入群申请审批」两个开关，但仍受群环境白名单和会话插件启停控制。

### 消息违禁词：禁言与撤回

开启「违禁词自动禁言」并填好词表后，群消息正文包含任一违禁词，就按「违禁词禁言时长」禁言发送者，默认 **10 分钟**。时长支持 `30秒`、`10分`、`2小时` 等，纯数字按分钟，必须大于 0 且不超过「⑦ 安全限制」里的最长秒数。

「违禁词消息撤回」用同一份词表，但开关独立——可以只撤回、只禁言，也可以两个都开。命中后先尝试撤回，撤回失败继续尝试禁言；禁言参数出错也不影响撤回。

QQ 的[撤回接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages_message_id.delete.html)要求：机器人是群管理员、消息来自普通成员、发送未超过 **2 分钟**。插件直接使用当前事件的 `message_obj.message_id`（原始消息的 `d.id`），不取引用消息 ID，也不保存触发消息的正文或 ID；缺少 ID 时跳过撤回并记日志。因此本功能不需要插件存聊天记录，AstrBot 或其他插件自己的记录行为由各自配置决定。

**成功失败都不发群提示**，失败只记日志；命中的消息会终止后续指令与 LLM 处理。只检查本条消息的文字，不检查引用原文、图片、语音，机器人自己的消息跳过。

两个例外：有权限的群管在 `群管功能` 里查看或调整配置时，指令里的词条不会误触发禁言；有权限的群管引用本群有效待审申请发审批指令时优先审批，拒绝理由里的违禁词不会误伤。普通聊天不因管理员身份豁免，能否禁言最终由 QQ 接口权限决定。

检测范围仅限于机器人实际收到并进入插件流程的消息，QQ 没投递的消息查不到。该功能不依赖「禁言指令」或 LLM 工具开关。

开启分群后，功能开关、词表、匹配模式、优先级和禁言时长都能按群独立设置；群内修改只作用于当前真实群的 UMO，并自动保存到面板的群列表。全局模式下，修改权限仅限 AstrBot 管理员，群管只能查看。

### 链接消息自动撤回

「⑧ 关键词管理 → 撤回链接消息」与违禁词开关独立。开启后，只要消息文字中出现 `https://`、`http://`、`www.` 开头的网址，或 `example.com`、`example.cn` 这类常见域名，就自动撤回该消息，不区分大小写。

该功能只检查本条消息的纯文字内容；图片、文件、语音等非文字消息不受影响。机器人自身消息和插件群管/QQ 群主管理员的消息会被跳过，避免误撤回公告。撤回失败只记日志，不发群提示。分群模式下同样可以按群单独开启。

开启后还可以在下方「撤回后发送提醒」里填写提醒文字，链接消息被成功撤回后会以回复形式发送到群里；该配置留空则不发送任何提醒。提醒只在撤回成功时发送，撤回失败不会触发。

### 二维码图片自动撤回

「⑧ 关键词管理 → 撤回二维码图片」用于拦截群里的二维码图片。开启后，插件会下载消息中的图片并识别二维码，识别成功时自动撤回该图片消息；普通照片、表情包等非二维码图片不受影响。

该功能需要 `zxing-cpp` 依赖（已写入 `requirements.txt`）。插件激活时会在后台检查，缺失时自动调用 AstrBot 的 pip 安装器补装，无需手动操作；若自动安装失败，插件仍可正常启动，只是不会识别和撤回二维码图片，并会在日志中提示，此时可手动执行 `pip install zxing-cpp`。

二维码撤回有独立的「撤回后发送提醒」输入框，与链接提醒分开保存，互不影响；同样留空则不发送提醒，提醒只在撤回成功时发送。

### 群内快捷管理

`群管功能` 会展示白词、黑词、违禁词的数量和预览，并提供查看、添加、删除、切换匹配模式、切换优先级、修改时长的快捷入口。点一下只是填入指令，补全后**发送出去才保存**。词表每页 10 条。

| 指令示例 | 效果 |
| --- | --- |
| `群管功能 入群关键词审批 开启` | 开启回答白黑词审批 |
| `群管功能 违禁词禁言 开启` | 开启消息违禁词禁言 |
| `群管功能 违禁词撤回 开启` | 开启消息违禁词撤回（可与禁言独立） |
| `群管功能 链接消息撤回 开启` | 开启链接消息自动撤回 |
| `群管功能 二维码图片撤回 开启` | 开启二维码图片自动撤回 |
| `群管功能 进群白词 添加 天文` | 回答包含「天文」即命中白词 |
| `群管功能 进群黑词 添加 广告` | 回答包含「广告」即命中黑词 |
| `群管功能 进群匹配模式 设置 正则匹配` | 切换进群白黑词为正则，可设回包含匹配 |
| `群管功能 违禁词 添加 bad phrase` | 添加完整词条，支持空格 |
| `群管功能 违禁词 查看 2` | 查看第二页，点删除链接可填入删除指令 |
| `群管功能 违禁词 删除 bad phrase` | 删除对应完整词条 |
| `群管功能 违禁词 清空 确认` | 清空该词表 |
| `群管功能 白黑词优先级 设置 白词优先` | 调整同时命中时的处理规则 |
| `群管功能 违禁词时长 设置 30分` | 调整禁言时长 |

`进群白词`、`进群黑词`、`违禁词` 都支持查看、添加、删除、清空。包含模式下重复添加同名单词（忽略大小写）不会重复保存；正则模式按原样区分词条。指令前缀遵循 AstrBot 的唤醒词设置。

## 🚦 刷屏监控

在面板「刷屏监控」里开启，或由有权限的群管发送 `群管功能 刷屏监控 开启`。开启后按每位成员最近 **1 秒 / 1 分钟 / 1 小时**的消息数统计，超过任一非零上限时自动撤回其近期消息并禁言。

| 配置项 | 说明 |
| --- | --- |
| 最近1秒上限 | 默认 5 条/秒，0 表示关闭该窗口 |
| 最近1分钟上限 | 默认 20 条/分，0 表示关闭该窗口 |
| 最近1小时上限 | 默认 0（关闭） |
| 夜间限速 | 开启后 22:00-06:00 使用更严格的最近 1 分钟上限 |
| 夜间阈值 | 夜间最近 1 分钟上限，0 表示不调整 |
| 禁言时长 | 默认 300 秒，支持 `30秒`、`10分` 等写法 |
| 撤回阈值 | 触发时撤回该成员最近消息的条数上限，默认 10 条 |

触发后会先标记处罚状态，在禁言时长内不会重复撤回和禁言。机器人自身消息、插件群管和 QQ 群主/管理员的消息会被跳过。WebUI「刷屏监控」页面会展示防刷屏状态、追踪群数、追踪用户、活跃用户、当前速率限制和实时追踪用户表，每 5 秒自动刷新。分群模式下，每个群可以单独设置开关与阈值。

<a id="server-status"></a>

## 🖥️ 服务器运行状态

WebUI「服务器运行状态」只保留总览页，展示：

- CPU、内存、SWAP、磁盘使用率
- 网络实时速率与累计流量
- 运行时间、进程数
- QQ 官方平台在线状态和插件已知群数
- 系统信息与 CPU 占用前 6 个进程

页面每 5 秒刷新。配置入口位于页面底部，可设置采样间隔、卡片透明度和毛玻璃模糊，并上传 PNG/JPG 状态图片（最大 5MB）。状态图片的标题、指标卡和系统信息卡支持毛玻璃透明度与模糊强度调节。这些配置也会同步到 AstrBot 插件配置的「服务器运行状态」分组。

QQ 官方平台限制：好友数、全部群成员数、OneBot 协议版本和 QQ 头像不可用，因此界面不展示；群聊数量使用插件已知群数，在线状态使用 QQ 官方平台实例状态。

### 群内指令 `查看状态` / `状态`

- **QQ 官方平台**：保持原有行为，仅群聊可用，图片走官方媒体上传接口，失败降级为文字。
- **其他平台**（aiocqhttp/OneBot、Telegram 等）：群聊和私聊都可以使用，状态图片通过 AstrBot 通用消息链发送，发送失败自动降级为文字摘要；文字摘要只包含 CPU、内存、磁盘、网络和采样间隔，不含 QQ 专属信息。

### LLM 群管工具

提供禁言、解禁、状态查询、申请列表、申请审批五类工具。

「⑥ LLM 群管工具 → 严格审查唤醒人权限」默认**关闭**：

- **关闭**：由模型自主决定调用，以机器人的权限执行，不按唤醒人身份拦截。
- **开启**：五个工具都会校验真实唤醒人的群管权限，普通成员连查询工具也调不动。

该开关可按群单独设置。工具结果回传给模型由它自然回复；「关闭禁言和解禁的固定成功提示」只作用于人工指令的成功提示，不影响错误提示和模型回复。

### 配置面板的层级

- **关闭分群**：只显示全局配置，各群统一使用。已有的群条目会保留，不会丢。
- **开启分群**：显示 UMO 列表，每个条目可单独设置群管权限、指令、申请审批、成员通知、LLM 工具、安全限制和完整关键词规则。关闭某个关键词功能时，对应词表和时长只是收起，内容不删除。
- **群内首次修改**：自动创建当前群的 UMO 条目，复制当时的全局配置，再叠加本次修改。之后该群走独立配置。
- **面板手动新增**：模板用插件默认值，请填真实群 UMO 并逐项核对后保存。没有建条目的群继续使用全局配置；删除条目即恢复该群继承全局配置。
- **群备注**：群组页可以给 `group_openid` 添加备注，例如 QQ 群号或群名。备注只用于显示，不会改变 UMO 或 AstrBot 的群识别。
- **群身份格式**：`平台ID:GroupMessage:group_openid`，与发送者无关。QQ 官方机器人返回的群 ID 是 `group_openid`，不是 QQ 群号；请直接复制 `群管功能` 或控制台群组页显示的 UMO，不要替换成群号。开启 AstrBot 独立会话也不会把群配置存到用户名下。群白名单同样填这个 UMO，不要填独立会话下 `sid` 返回的用户 UMO。
- **面板同步**：群内改动立即写入插件配置文件，重新打开面板就能看到。已经打开的表单不会自动刷新——群内改完请先重新打开面板再编辑，避免旧表单覆盖新值。面板保存后由 AstrBot 重载插件生效。
- **控制台配置页**：WebUI 的「群管控制台 → 配置」与原生配置面板读写同一份配置；控制台保存后立即生效，不需要再回原生面板。分群配置条目也可以在这里创建、编辑和删除。保存或创建分群配置会自动开启分群覆盖，避免出现“保存后仍读全局值”的情况；分群选择器优先显示群名，没有群名时显示群 UID。

群白名单和待审记录保留天数是全局项；保留天数在关闭分群时的全局入群申请配置里设置。分群模式下修改全局配置不会覆盖已有群条目。

### 旧配置迁移

首次加载会把旧全局配置和 `state.json` 里的分群开关迁入新面板：先复制当时的全局有效值，再叠加各群的旧开关。迁移前的配置与旧分群记录保存在插件数据目录的 `group-config-before-v2.json`；`state.json` 里的旧记录也保留，但不再作为新分群配置的写入目标。迁移标记保证删除群条目后，重启不会从旧存储重新导入。

**无法自动还原的情况**：旧版在独立会话模式下可能把用户 ID 当成群 ID 存下来，原记录里没有所属群信息。检测到当前启用独立会话、又无法从待审记录确认群归属时，对应条目会被标为待确认并暂不应用。处理办法：在真实群里发 `群管功能` 拿到 UMO，修正条目后勾选「已确认 UMO 属于目标群」。如果以前开过独立会话、后来关掉了，历史状态无法从配置判断，也请人工核对旧 UMO——插件不会把用户 ID 猜成某个群。

迁移或群内配置保存失败时不会保留未落盘的新配置。

### 与 AstrBot 会话设置的关系

当前会话的插件启停设置同样生效：当前配置没启用本插件，或已在会话内禁用，自动通知和旧申请卡片的审批按钮也会停止工作。

## 🗃️ 数据、备份与恢复

### 数据放在哪

| 内容 | 位置 |
| --- | --- |
| 群管名单、待审映射、验证记录 | `data/plugin_data/astrbot_plugin_qq_group_manage/state.json` |
| 控制台主题色偏好 | `data/plugin_data/astrbot_plugin_qq_group_manage/state.json` 的 `ui_preferences` |
| 自动记录的群组 | `data/plugin_data/astrbot_plugin_qq_group_manage/state.json` 的 `seen_groups` |
| 群备注 | `data/plugin_data/astrbot_plugin_qq_group_manage/state.json` 的 `group_notes` |
| 接口获取的群名 | `data/plugin_data/astrbot_plugin_qq_group_manage/state.json` 的 `group_names` |
| 群 UID 编号 | `data/plugin_data/astrbot_plugin_qq_group_manage/state.json` 的 `group_ids` / `free_group_ids` |
| 群配置与词表 | AstrBot 插件配置文件的 `group_management.groups` |
| 全局设置 | AstrBot 插件配置文件的 `group_management.global_settings` |

`state.json` 里保存的是：插件群管名单、迁移前保留的旧分群开关、入群申请事件中的昵称、OpenID、验证内容、消息引用和审批按钮映射，以及进群验证成员的 OpenID、题目、答案和答错次数。

机器人被移出群时，插件监听 QQ 的 `GROUP_DEL_ROBOT` 事件，直接删除该群的已知群记录、备注、群管名单、待审、验证和分群配置，不保留归档。

机器人被邀请进群时，插件监听 `GROUP_ADD_ROBOT`，会立即把该群加入已知群列表，不需要等群里先发消息。

验证记录只在**验证通过、退群或管理员放行**时删除，不受待审记录保留天数影响——所以验证失败的成员不会因为时间过去而被自动放行。

待审映射与审批完成标记默认保留 **30 天**：审批成功后移除待审内容，只留平台 ID、群 OpenID、申请 ID 和完成时间用于去重；过期记录在加载、查找、写入时顺带清理，不是定时任务。群管名单和群配置长期保存；群管名单的批量修改一次落盘，写盘失败则整批回滚并提示。

备份时请**同时**备份插件配置文件和插件数据目录。也可以直接打开「群管控制台 → 数据」导出 `state.json` 与配置快照。数据页同时支持安全导入：先校验版本、字段和分群 UMO，显示将影响的群管/待审/验证/群组/配置数量；可选择「合并」或「覆盖」，导入前自动把当前 `state.json` / 配置写成 `*.bak-时间.json` 备份，写入失败会回滚。

### 会发给模型的数据

调用 LLM 申请列表工具时，申请内容和审批所需 ID 会作为工具结果交给 AstrBot 配置的模型服务；人工审批卡片则会在目标群展示申请内容。

### 恢复与损坏处理

备份或恢复前先停用插件，再复制或替换 `state.json`。

如果文件损坏，插件会把原文件保留为同目录下的 `state.corrupt-随机标识.json`，在日志里给出路径，并以空状态启动：原群管名单和旧申请映射暂时失效，已迁移到配置文件的群配置不受影响。修好备份后，停用插件、把它放回 `state.json` 再启用即可。若连损坏文件都无法保留，插件会停止加载，避免覆盖原有数据。损坏备份不会自动清理。

需要彻底清空本地数据：停用插件，删除上述状态文件及不再需要的损坏备份。注意这不会撤销 QQ 里已经执行的禁言或审批，也不会删除群消息和模型服务已接收的数据。

## 💡 常见限制速记

| 现象 / 限制 | 原因与对策 |
| --- | --- |
| 撤回没生效 | 只对 2 分钟内、普通成员的消息有效，且机器人必须是群管理员 |
| 验证题发不出来 | 主动消息受每群每日额度限制，耗尽时改为等成员发言再补发 |
| 想让验证失败的人退群 | QQ 没开放移出成员接口，只能禁言 |
| 按钮点了没反应 | 缺自定义 Markdown/按钮权限，或 Webhook 未订阅 `INTERACTION_CREATE` |
| 违规消息检测不到 | 机器人只收到 @ 消息时无法检查全部群消息 |
| 面板显示旧配置 | 已打开的表单不会自动刷新，重新打开面板再改 |
| 看不到群管控制台 | 确认 AstrBot 不低于 4.26.0，插件已启用，并在插件详情页刷新后打开「可视化视图」 |
| 控制台操作失败 | 查看 AstrBot 日志；审批/放行还要求对应 QQ 平台在线且有接口权限 |
| 分群配置对不上号 | 用真实群发 `群管功能` 取得的 UMO，别用独立会话下的用户 UMO |
